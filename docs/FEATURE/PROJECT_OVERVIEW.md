# HA'WE (하웨) — 프로젝트 소개

> 이 문서는 **프로젝트를 처음 보는 사람이나 AI**에게 HA'WE가 무엇인지 설명하기 위한 문서다. 저장소를 보지 못해도 이해할 수 있게 썼다.
> 상태 표기: **확정**(결정됨) / **초안**(임시로 정한 값) / **미정**(결정 필요) / **구현됨**(코드 있음) / **설계만**(문서만 있음).

## 1. 한 줄 요약

**그룹마다 매일 미션이 열리고, 내가 먼저 답해야 그룹원들의 답을 볼 수 있는 모바일 그룹 앱.**

- 이름: HA'WE (하웨). "하루, 날것 그대로 — today, raw as it is"라는 뜻.
- 꾸미지 않은 하루를 가볍게 나누는 것이 목적이다. 사진·글·그림·슬라이더 같은 짧은 놀이 형태의 미션을 쓴다. (음성은 2026-10-12 결정으로 제거했다.)
- 사용자는 모두 성인이다. 톤은 친구에게 말 거는 가벼운 반말.

## 2. 누가, 왜 쓰는가

- **사용자:** 연인, 가족, 친구처럼 이미 알고 있는 소규모 그룹. 그룹의 6자리 코드로 미리보기 후 참여한다(연인 2명, 그 외 최대 6명).
- **문제:** 소규모 그룹은 평소 연락이 뜸하거나 일상을 공유하는 일이 부담스럽다.
- **해결:** 정해진 시각에 가벼운 미션이 열리고, 답하면 서로의 답이 보인다. "남의 답이 궁금해서" 참여하게 되는 구조다.
- **그룹 관계** 5종: 연인, 가족, 친구, 웬수(티격태격하는 라이벌), 그저그런사이. 관계에 따라 어울리는 미션 톤과 금지 주제가 다르다 (§7).

## 3. 핵심 규칙

| 규칙 | 내용 |
|---|---|
| **잠금(제출해야 열람)** | 내가 그 미션에 답하기 전에는 그룹원의 답(피드)과 집계 결과를 볼 수 없다. 화면에서는 블러 처리된다. |
| **미션** | 그룹마다 하루에 N개(그룹이 설정)가 정해진 시각에 자동으로 열린다. 사용자가 만드는 것이 아니라 AI가 생성한다. |
| **제출** | 미션당 1인 1회. 틀(§4)이 요구하는 형식으로 낸다. |
| **마감과 지각** | 마감 이후 같은 슬롯의 다음 미션이 열리기 전까지 지각 제출할 수 있다. 종료 판정은 제출 API 구현 단계에서 적용한다. |
| **도장** | 그룹 달력에 날짜별로 내 도장이 찍힌다: "참잘했어요"(마감 전 제출), "지각"(마감 뒤 제출), "벌점"(안 냄 + 미션이 닫힘 + 미션이 열릴 때 이미 멤버였음). 아직 낼 수 있는 미션이나 들어오기 전 미션은 도장 없음. 별도 저장 없이 제출 기록으로 계산한다. 하루 미션이 여러 개면 **미션마다** 도장이 따로 찍힌다(B7 결정). |
| **재촉** | 아직 안 낸 멤버에게 "콕찌르기" 또는 "똥뿌리기"를 보낼 수 있고, 알림이 간다. |
| **상호작용** | 게시물에 스티커 반응(토글)과 댓글(`@멘션`, 사진 첨부)을 남길 수 있다. |
| **알림** | 미션 도착, 콕찌르기, 댓글, 멘션 등. |
| **마이페이지** | 활동 요약(완료 미션 수, 연속 참여 일수, 참여 그룹 수, 유형별 수), 프로필 캐릭터 선택. 달력은 그룹별로 미션 화면에서 연다. |

## 4. 미션 "틀(템플릿)"

미션은 **틀 + 빈칸 + 문장**으로 만든다. 틀은 놀이 방식이고, 빈칸은 그 틀이 요구하는 입력값이다.
예: 틀 `삼행시`, 빈칸 `제시어=퇴근길` → 미션 문장 "퇴근길로 삼행시 지어줘".

사용자가 답하는 매체는 4가지다. (음성 매체와 음성 틀 3종 — 한 줄·소리 흉내·성대모사 — 은 2026-10-12 음성 기능 제거로 없어졌다.)

| 매체 | 틀 예시 (총 18종 중 일부) | 제출물 |
|---|---|---|
| 사진 | 지금 이 순간, 갤러리 발굴, 색깔 사냥 | 이미지 + 캡션 |
| 글 | 삼행시, 한 단어 일기, 한 줄 후기, 밸런스 게임, 빈칸 채우기 | 글 / 별점 / A·B 선택 |
| 그림 | 30초 스케치, A를 B로 | 앱 그림판의 그림 |
| 슬라이더(클릭) | 내 위치는?, 취향 막대, 다수결 예측 | 0~100 위치 (+ 예측값) |

틀은 성격에 따라 나뉜다.

| 유형 | 설명 | 상태 |
|---|---|---|
| 단독 제출 | 각자 혼자 내면 끝 (사진, 삼행시 등) | 1차 |
| ~~정답 맞히기~~ | 폐기됨. 성대모사·소리 흉내가 음성 제거로 없어져 해당 틀이 없다. 그림 맞히기 AI 게임은 서버 틀이 아니라 기기 안에서 동작한다 | 폐기 |
| 대상 지정 | 그룹 멤버 한 명이 미션에 지목됨 (빈칸 채우기는 항상, 그림 틀은 일정 확률로) | 1차 (정책 검토 중) |
| 집계 | 제출값을 모아 평균·비율·순위를 보여줌 (밸런스 게임, 슬라이더) | 1차 |
| 순서·역할 | 앞사람 결과를 이어받거나 출제자/맞히는 사람이 나뉨 (끝말 이어쓰기, 갈틱폰, 제시어 바 등) | 2차, 별도 설계 필요 |

## 5. 그룹 설정 (하루 미션 수와 시각)

- 그룹이 **하루 미션 수를 1~5개**로 정한다(`hawe.mission.max-daily-count=5`, 기본 1 — B7). 지금 앱에는 설정 화면이 없어 하루 1개이고, 앱의 여러 미션 화면은 A6이다. 슬롯 간 최소 간격은 없다.
- 하루 미션 수를 줄이면 이미 열린 미션은 그날 유지되고, 없어진 슬롯의 미션은 다음 날 첫 발행에서 닫힌다.
- 미션 순번(슬롯)별로 **발행·마감 시각**을 정할 수 있다. 지정하지 않은 슬롯은 설정 파일(`hawe.mission.*`)의 기본 시각(발행 09:00, 마감 23:00 — 초안)을 쓴다. 그룹 자체에는 시각 설정이 없고 슬롯이 전담한다.
  - 예: 하루 3개, 1번은 지정 없음(09:00~23:00), 2번은 14:00~22:00, 3번은 19:00 발행(마감은 기본).
- 미션이 열릴 때 발행·마감 시각을 미션에 고정 저장한다. 이후 설정을 바꿔도 이미 열린 미션과 지각 판정은 바뀌지 않는다.

## 6. AI의 역할

AI는 미션 문장을 생성한다. 사진 틀(`PHOTO_NOW`, `PHOTO_COLOR`)은 별도 비전 서비스가 주제 적합도 점수를 계산하고 서버가 긍정 배지·칭찬 문구만 판정한다(B10). 점수나 부정 평가는 사용자에게 보이지 않으며 도장은 제출 여부만으로 정해진다. 미션 생성 제공사는 **Claude API**(Anthropic)로 정했고 Spring AI 없이 서버가 직접 부른다(B8, 2026-10-13). 키가 없거나 꺼져 있거나 실패하면 고정 문장을 쓴다. 상세: `MISSIONS_API.md` §6-2, `VISION_TOPIC_FIT.md`.

- **틀은 서버가 정한다.** 서버가 그날의 틀(예: 삼행시)을 정해서 AI에게 주고, AI는 그 틀 안에서 `{문장, 카테고리, 빈칸 값}`만 만든다. AI가 틀을 고르거나 바꾸지 않는다. 틀 선택 규칙: 하루 미션이 여러 개면 같은 날 매체(사진/글/그림/슬라이더)가 겹치지 않게(슬롯이 매체보다 많으면 같은 매체의 다른 틀), 하루 1개면 어제와 같은 매체를 피한다. 후보가 부족하면 예외를 허용하고, 그룹 관계별 선호는 두지 않는다.
- **입력:** 오늘 날짜/요일, 그룹 관계, 선택된 틀과 그 빈칸 정의, 대상 유무, 최근 미션(문장·카테고리·틀), 카테고리 목록, 그리고 그룹 맞춤용 **특별한 날**(연인 100일 단위·주년, 그룹 100일·주년, 설정한 날)과 **그룹 기록**(최근 미션별 참여율·반응 수, 매체별 참여율 — 미션 단위 숫자만).
- **보내지 않는 것:** 멤버 이름·닉네임, 그룹 이름, 제출한 글·사진·댓글 내용.
- **효과 측정 (B9):** (그룹, 날짜)마다 AI 주제와 랜덤(고정 문장) 주제를 무작위로 나눠 참여율·정시 제출·반응·첫 제출 시간을 비교한다. 사용자는 어느 쪽인지 모른다(블라인드). 그룹 안에서 AI 날과 랜덤 날을 비교한 값을 주 지표로 보고, 표본이 작으면 경고와 함께 낸다. 기본 꺼짐. 상세: `docs/BACKEND/EXPERIMENT_TOPIC.md`.
- 날씨·사는 곳·멤버 이름 같은 정보는 주지 않으며, 짐작해서 넣지 않는다.
- **서버가 결과를 반드시 재검증한다** (예: 삼행시 제시어가 정확히 3글자인가, 빈칸 값이 틀의 형식에 맞는가, 최근 미션과 겹치지 않는가). 실패하면 재시도하고, 계속 실패하면 예비 미션을 쓴다.
- 사진 제출물은 설정된 내부 비전 서비스에만 보내 주제 적합도를 계산한다. 미션 생성 AI에는 제출물·사진을 보내지 않는다.

## 7. 미션 안전 규칙 (AI 생성 시 지킬 것)

**모든 관계 공통 금지:** 폭력·자해, 성적 내용, 혐오·차별, 위험하거나 불법인 행동, 음주·도박 부추김, 외모·몸·체중, 돈, 위치·개인정보(집·학교·회사, 영수증 등), 다른 사람을 몰래 찍거나 녹음, 무거운 주제(이별·죽음·병·트라우마), 정치·종교 같은 편 가르기, 욕설·비속어, 이모지.

**좋은 미션 조건:** 오늘 안에 누구나 답할 수 있어야 하고(특별한 장소·준비물 불필요), 답하는 데 1~2분이면 되고, 한 번에 하나만 묻고, 한 문장(30자 안팎)이며, 사람마다 답이 달라 궁금해져야 한다.

**관계별 주의 (요약)**

| 관계 | 방향 | 피할 것 |
|---|---|---|
| 연인 | 다정하고 설레는 미션. 그림 적합 | 감시(어디야, 누구랑), 질투, 상대가 해준 것 평가, 관계 점수 |
| 가족 | 따뜻하고 쉬운 미션. 사진·슬라이더 적합 | 나쁘게 평가하는 미션 전부(가족이 해준 것일 수 있음), 잔소리 주제(결혼·취업·성적), 형제 비교 |
| 친구 | 장난·솔직함. 모든 방식 적합 | 특정 친구 한 명 놀리기, 서열 매기기, 뒷담화 |
| 웬수 | 서로 놀리는 재미는 살리되 상처는 금지. 그림·슬라이더 적합 | 바꿀 수 없는 것(외모·가족·학력·경제) 놀리기, 여러 명이 한 명을 공격, 실제 적대감 |
| 그저그런사이 | 어색함 풀기. 슬라이더 최적 | 사생활, 친한 사이 전제 표현, 얼굴·목소리를 많이 드러내는 미션 |

핵심 원칙: **"평가 대상이 그룹 안의 누군가가 만들었거나 준 것일 수 있으면, 나쁘게 평가하는 미션은 만들지 않는다."**

**검토 중인 위험 틀:** `빈칸 채우기(랜덤 사람 지정)`는 여러 명이 한 명에 대해 쓰는 구조라 위 규칙과 충돌할 수 있어 허용 범위(긍정적 문장만, 관계별 허용 등)를 정하는 중이다.

## 8. 기술 구성

| 영역 | 내용 | 상태 |
|---|---|---|
| 백엔드 | Spring Boot 4.1.1 (Java 25, Maven), MariaDB, MyBatis(어노테이션 SQL), Flyway 마이그레이션, JWT 인증(stateless) | |
| 프론트엔드 | 네이티브 앱 2종. iOS = SwiftUI(`ios/`, iOS 17+), Android = Kotlin + Jetpack Compose(`android/`, minSdk 26). 화면은 모두 구현, 앱 안 임시 저장소(`DataStore`)로 동작하며 API 연결 없음 | 화면 구현됨 |
| 저장소 | 이미지 파일: 개발=로컬 디스크, 운영=S3(서버가 파일을 직접 받아 내부에서 저장) | 설계 |
| 스케줄·푸시 | 미션 발행은 스케줄러(EventBridge), 푸시는 SNS | 설계 |
| 추후 | 회고 추천(Qdrant 벡터 검색, 과거 비슷한 감정의 글 찾기) | MVP 제외 |

- 로그인은 이메일/비밀번호 **자체 가입**이다 (소셜 로그인은 MVP 제외). 액세스 토큰 30분, 리프레시 토큰 14일.
- 코드 구조는 기능별 패키지(`auth`, `group`, `mission` …) 안에 controller → service → dao → domain/dto 계층을 둔다. 에러는 기능별 에러 코드 enum을 `BusinessException`으로 던져 전역 핸들러가 `{code, message}`로 응답한다.
- API는 REST(`/api/...`), JSON은 camelCase, 목록은 `{content, page, size, totalPages, totalElements}` 봉투를 쓴다.

## 9. DB 개요

사용자 → 그룹 가입 → 그룹별 미션 → 제출 → 댓글·반응이라는 흐름이다.

| 테이블 | 역할 |
|---|---|
| `users`, `characters` | 회원, 프로필 캐릭터 |
| `groups`, `group_members` | 그룹(6자리 초대 코드·연인 시작일·하루 미션 수), 가입 관계(`owner`/`member`) |
| `group_mission_slots` | 슬롯별 시각 재정의 (바꾼 슬롯만 저장) |
| `missions` | 그날의 미션 (틀 코드 `template`, 빈칸 JSON `params`, 슬롯 번호, 발행·마감 시각) |
| `submissions` | 제출물. 틀에 따라 파일 / 글 / 숫자 / 선택 / 예측 칸 중 필요한 것만 채움 |
| `submission_guesses` | 정답 시도 기록 — 미사용(잔재, 음성 제거로 정답 맞히기 폐기) |
| `comments`, `comment_mentions`, `reactions` | 댓글, 멘션, 스티커 반응 |
| `pokes`, `notifications` | 재촉, 알림 |

DB가 중복을 막는 것: 한 그룹에 같은 사용자 중복 가입, 같은 슬롯 중복 발행, 한 미션에 한 사람의 중복 제출.

## 10. 현재 진행 상태

| 영역 | 상태 |
|---|---|
| 인증·Me API (가입·로그인·토큰 재발급·기본 프로필·탈퇴) | **백엔드 구현됨** (`PATCH /me/password`는 후속) |
| 그룹 API (생성·목록·상세·설정·멤버·코드 미리보기·가입·후임자 나가기) | **백엔드 구현됨** (그룹 내 프로필은 후속) |
| 미션·제출·집계 API | **백엔드 구현됨** (지원 틀은 단계별로 확장) |
| 댓글·반응·콕찌르기·캐릭터 API | **백엔드 구현됨** (앱 연결은 단계별) |
| 알림 API | 설계만 |
| 그룹 달력·활동 요약 API | **구현됨** (Android·iOS 연결됨, iOS는 Mac 빌드 확인 전) |
| 프론트엔드 (iOS·Android 네이티브) | 화면 구현됨, 백엔드 연결 단계별 진행 중 |
| AI 연동 | 미션 문장 AI 생성·서버 검증·고정 문장 폴백 구현(B8, 기본 꺼짐 — 키를 넣고 켜야 동작), AI 주제 vs 랜덤 주제 비교 실험·리포트(B9, 기본 꺼짐). 프롬프트는 팀원이 작업 중 |

팀은 사람(검토·git 관리)과 AI 에이전트 두 종류(구현, 리뷰·디버깅)로 역할을 나눠 작업한다.
