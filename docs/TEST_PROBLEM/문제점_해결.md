## 1. 갤러리 미션 버튼 → 해결 (Android) · 3. 찍는 미션에 예전 사진 → 해결 (Android)

사진 미션은 **미션에 맞는 방법 하나만** 보여 줘요(2026-10-19 팀 결정).

| 미션 | 미션 카드 버튼 | 수행 화면 |
|---|---|---|
| 갤러리 발굴 (`PHOTO_GALLERY`) | **갤러리 둘러보기** | 카메라를 켜지 않고 **[갤러리 둘러보기]** 버튼 하나. 카메라 권한도 묻지 않아요 |
| 지금 이 순간 · 색깔 사냥 | **사진 찍기** | 카메라 + 셔터 + 전환 버튼. **갤러리 아이콘을 없앴어요**(예전 사진을 올릴 수 없어요) |

- 고친 곳: `MissionFormat.kt` `missionActionTitle`, `PhotoMissionScreen(topic, template, …)`(`MissionPerformScreen`에서 틀을 넘겨받아요)
- 고른 뒤 버튼: 갤러리 미션은 **"다시 고르기"**(누르면 갤러리가 바로 다시 열려요), 찍는 미션은 "다시 찍기"

## 2-1. 문장 문법 오류 → 해결 (서버)

- 받침에 맞는 조사를 고르는 `KoreanJosa`를 새로 만들었어요(`global/text/KoreanJosa.java`). 앱의 `KoreanText.kt`와 같은 규칙이에요.
- **예비 문장**(`PlaceholderMissionGenerator`)
  - "구름을 풍선**으로** 바꿔 그려줘", "책을 집**으로** 바꿔 그려줘"
  - 30초 스케치("~을/를 30초 안에 그려줘")와 삼행시("~으로/로 삼행시를 지어줘")에도 같이 적용했어요.
- **[대상] 자리에 닉네임을 넣을 때도 조사를 맞춰요**(`MissionService`, `CalendarService`).
  - 예: "[대상]을" → "찬희**를**", "[대상]와" → "우준**과**"
  - 바꾸는 조사: 을/를, 이/가, 은/는, 과/와, 으로/로, 이랑/랑
  - **AI가 쓴 문장에도 적용**돼요. 예전에는 AI 문장이어도 닉네임에 따라 "찬희을"처럼 나올 수 있었어요.
- 예전의 틀린 결과("잎사귀은")를 정답으로 적어 둔 테스트가 하나 있어서 "잎사귀는"으로 고쳤어요(`MissionServiceTests`).

## 2-2. "A를 B로" 미션 뜻 → 해결 (Android)

- 미션 카드와 그림 그리는 화면의 제목 아래에 **안내 한 줄**이 나와요(`templateGuideText`).
  - "‘구름’을 ‘풍선’처럼 보이게 바꿔서 그려요"
  - 대상이 사람이면 이름을 빼고 "‘풍선’처럼 보이게 바꿔서 그려요"
- 그림 화면에 있던 **"‘구름’를 ‘풍선’로"** 문구(조사가 틀렸던 것)를 이 안내로 바꿨어요(`DrawMissionScreen`).

## 2-3. 그림 AI 판정 → 해결 (Android, 범주 파일)

- **"A를 B로"는 A나 B 중 하나만 알아봐도 맞힌 걸로 쳐요.**
  - 예: "구름을 풍선으로"에서 AI가 '구름'이라고 하면 "AI가 맞혔어요!"
  - 2·3등에 A나 B가 있으면 "아깝게 놓쳤어요"
  - 대상이 사람이면 지금처럼 B만 봐요.
  - 고친 곳: `DrawSubjectMatcher.subjects`, `aiVerdict(guesses, subjects)`, 결과·상세·그림 화면 세 곳의 호출
- **'풍선'을 '열기구'의 다른 이름에서 뺐어요.** 이제 '풍선'은 모델에 없는 단어라서 판정 없이 AI 추측만 보여 줘요.
  - 범주 파일 3곳을 똑같이 고쳤어요: `ml/quickdraw/categories.json`(원본), `android/.../assets/quickdraw/categories.json`, `ios/HAWE/Resources/QuickDraw/quickdraw-categories.json`
  - 모델은 다시 학습하지 않아도 돼요(이름 목록만 바뀜).

## 추가: 사진 AI가 항상 실패하던 버그 → 해결 (서버)

- **증상:** 사진을 올려도 배지나 한마디가 안 떴어요. DB 기록(`submission_ai_reviews`)에는 모두 `FAILED`로 남았어요.
- **원인:** 서버가 비전 프로그램(Python, uvicorn)에 요청할 때 Java 기본 설정대로 **"HTTP/2로 바꾸자"(h2c 업그레이드) 신호**를 같이 보냈어요. uvicorn은 이 신호를 처리하지 못해서 요청을 **400 오류**로 거절했어요.
- **해결:** `VisionClient.java`에서 HTTP/1.1로만 통신하도록 고정했어요(한 줄).
- **테스트:** 실제 Java HTTP 클라이언트로 요청을 보내 업그레이드 신호가 없는지 확인하는 테스트를 추가했어요(`VisionClientTests.realClientStaysOnHttp11`). 고치기 전 코드에서는 이 테스트가 실패해서(`h2c`) 버그를 실제로 잡는 것도 확인했어요.
- **확인:** 비전 프로그램에 HTTP/1.1로 파란 이미지와 "파란색" 주제를 보냈더니 정상 응답(200, 점수 0.36)이 왔어요. 배지 기준은 0.132예요.
- **아직 할 일:** 휴대폰에서 실제 사진을 올려 결과 화면에 배지가 뜨는지 확인해야 해요.
- 그동안 이 기능을 가짜 서버로만 테스트해서 발견하지 못했어요.

## 5. 회원가입 중복 이메일 → 해결 (서버, Android)

- **증상:** AWS 서버에서 가입할 때 이메일·비밀번호를 쓰고 닉네임까지 정한 뒤 "시작하기"를 누르면 첫 화면(계정을 만들어요)으로 되돌아갔어요.
- **원인:** 그 이메일이 이미 가입돼 있었어요. 서버가 마지막 단계에서야 `EMAIL_TAKEN`을 알려 줘서, 앱이 "이미 가입된 이메일이에요"를 1.6초 보여 주고 이메일을 바꾸라고 첫 화면으로 돌아갔어요. 안내가 짧아서 놓치기 쉬웠어요.
- **해결:** 첫 화면 이메일 칸 옆에 **[중복 확인] 버튼**을 넣었어요. **확인을 통과해야 [다음]이 눌려요.**
  - 통과: "사용할 수 있는 이메일이에요"
  - 이미 가입됨: "이미 가입된 이메일이에요"(빨간 글씨)
  - 네트워크 오류: "확인하지 못했어요. 다시 눌러 주세요"
  - 확인한 뒤 이메일을 고치면 다시 확인해야 해요.
- **서버:** `POST /api/auth/email-check` → `{ "available": true/false }` 를 새로 만들었어요(`AuthController`, `AuthService.checkEmail`). 형식은 `docs/BACKEND/API_DESIGN.md`에 적었어요. 가입 요청도 예전처럼 중복을 다시 검사해요.
- **아직 이 기능이 없는 서버에서는(404)** 앱이 확인을 건너뛰고 예전처럼 가입할 때 서버가 검사해요. AWS에 배포되기 전에도 가입이 막히지 않게 하려는 거예요.
- **테스트:** 서버 `AuthServiceTests`, `AuthControllerValidationTests`, Android `SignupAccountStateTest.emailDuplicateCheck`

## 7. 삼행시 빈 줄 → 해결 (서버, Android)

- **증상:** 삼행시를 쓰다가 엔터를 두 번 눌러 빈 줄이 생기면 "3줄로 써 주세요"가 뜨고 [올리기]가 눌리지 않았어요.
- **원인:** 줄을 셀 때 맨 끝의 빈 줄만 빼고, 처음이나 중간의 빈 줄은 한 줄로 셌어요(Android, iOS, 서버 세 곳 모두).
- **해결:** **빈 줄(공백만 있는 줄 포함)은 아예 세지 않아요.** 빈 줄을 뺀 나머지가 정확히 3줄이고 각 줄이 제시어 글자로 시작하면 통과예요.
  - Android: `WriteMissionState.acrosticError`, 올릴 때는 빈 줄을 뺀 3줄(`submitText`)을 보내요. 그래서 아직 고치지 않은 서버(AWS)에도 올라가요.
  - 서버: `SubmissionService.validateAcrostic`가 빈 줄을 빼고 검사하고, 빈 줄을 뺀 3줄로 저장해요. 친구들 화면에도 깔끔하게 보여요.
- **테스트:** Android `WriteMissionStateTest`, 서버 `SubmissionServiceTests.textAndAcrosticRules`

## 참고: 예비 문장이 재미없음

- "지금 눈앞의 **작은** 물건을 찍어줘"는 AI가 꺼져 있을 때 쓰는 예비 문장이었어요.
- `.env`에 미션 AI 설정(`HAWE_MISSION_AI_ENABLED=true`, 게이트웨이 주소·키)을 넣으면 AI가 문장을 써요. 실제로 AI가 "지금 내 손 닿는 곳에서 제일 만만한 물건 찍어 와"를 만들었어요.
- AI 연결이 실패하면 예비 문장이 다시 나와요. 예비 문장을 더 재미있게 고치는 건 선택이에요.

## iOS에 남은 일 (경환)

Android에서 고친 내용을 iOS에도 똑같이 넣어 주세요. 범주 파일(`quickdraw-categories.json`)은 이미 고쳐 뒀어요. 끝나면 [문제점.md 4번](문제점.md)을 빼 주세요.

1. **사진 미션 버튼 나누기**
   - `TodayMission.actionTitle`에서 `PHOTO_GALLERY`이면 "갤러리 둘러보기"로 보여 주세요.
   - `PhotoMissionView`에 틀 값을 넘겨 주세요. 갤러리 미션은 카메라 없이 [갤러리 둘러보기] 버튼 하나만 두고, 고른 뒤에는 "다시 고르기"로 보여 주세요.
   - 찍는 미션(지금 이 순간, 색깔 사냥)은 `PhotosPicker`(갤러리 아이콘)를 없애 주세요.
2. **"A를 B로" 안내 한 줄:** 미션 카드와 그림 화면에 넣어 주세요. 문구와 조사 규칙은 Android `MissionFormat.kt`의 `drawToGuide`를 참고해 주세요.
3. **그림 AI 판정:** "A를 B로"는 A·B 둘 다 맞힌 걸로 쳐 주세요. Android `DrawSubjectMatcher.subjects`와 `aiVerdict(guesses, subjects)`를 참고해 주세요.
4. **회원가입 이메일 중복 확인:** 가입 첫 화면 이메일 칸 옆에 [중복 확인] 버튼을 넣고, `POST /api/auth/email-check`가 `available: true`일 때만 [다음]을 눌리게 해 주세요. Android `SignupAccountState`(문구·조건)와 `SignupAccountScreen`을 참고해 주세요.
5. **삼행시 빈 줄:** `WriteMissionView.swift`의 `acrosticError`에서 빈 줄(공백만 있는 줄 포함)을 세지 말고, 올릴 때도 빈 줄을 뺀 3줄을 보내 주세요. Android `WriteMissionState.submitText`를 참고해 주세요.

## 확인 방법

1. 휴대폰 앱에서 개발자 도구 → 미션 생성으로 아래 틀을 차례로 만들어 봐요.
   - `PHOTO_GALLERY`: 버튼이 "갤러리 둘러보기"인지, 들어가면 카메라 없이 갤러리 버튼만 있는지
   - `PHOTO_NOW`: 버튼이 "사진 찍기"인지, 화면에 갤러리 아이콘이 없는지
   - `DRAW_A_TO_B`: 안내 한 줄이 보이는지, A를 그려도 "맞혔어요"가 나오는지
   - `PHOTO_COLOR`: 주제에 맞는 사진을 올리고 5초쯤 뒤 결과 화면에 배지가 뜨는지
2. 사진 배지가 안 뜨면 서버 DB의 `submission_ai_reviews` 표에서 그 사진의 `status`와 `fit_score`를 봐요.
   - `FAILED`: 아직 연결 문제가 있어요.
   - 점수가 낮음: 정상이에요. 점수가 낮으면 일부러 표시하지 않아요.
