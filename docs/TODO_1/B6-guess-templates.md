# B6. (폐기) 정답 맞히기(G) 틀 — 소리 흉내·성대모사 + 정답 시도 API

> **상태: 폐기됨 (2026-10-12).** 사용자 결정으로 **음성 기능이 완전히 제거**되어(B0/A0) G 유형을 쓰던 두 틀 `VOICE_MIMIC`·`VOICE_IMPRESSION` 이 사라졌다. 따라서 이 계획(정답 시도 API `POST /api/submissions/{id}/guesses`, 제출 `answer`/`alias`, 피드의 `answer`/`myGuess`)은 **구현하지 않는다.** 실행 큐에서 제외하고, 다른 계획이 이 문서를 선행 조건으로 두던 부분은 아래 표처럼 정리했다.

## 왜 폐기하는가

- G 유형 틀 2종이 모두 음성 틀이었다(`MISSIONS_API.md` §1-2). 다른 매체에는 "제출자가 정답을 적고 다른 멤버가 맞히는" 틀이 정의돼 있지 않다.
- "친구 그림을 AI가 맞히는 게임"은 **서버 정답 시도 구조가 아니라 온디바이스 AI 추론**으로 하기로 했다(M1 모델 학습 → A8 앱 내 추론). 사람이 정답을 맞히는 서버 API 는 필요 없다.

## 남겨 둔 것 (스키마 잔재 — 결정 대기)

`submissions.answer_text`, `submissions.answer_aliases`, 테이블 `submission_guesses`, `MissionErrorCode` 의 예약 이름(`GUESS_*`)은 **지금은 사용처가 없다.** B0 에서는 8단계(탈퇴·그룹 삭제의 삭제 쿼리가 `submission_guesses` 를 참조)와의 충돌을 피하려고 스키마를 바꾸지 않았다.
- 기본값: **유지**(후속 R 유형 틀 — 그림 맞히기/갈틱폰 등 — 이나 서버 기반 게임에서 재사용 가능).
- 정리하고 싶다면 별도 작은 계획으로: V1 에서 컬럼·테이블 삭제 → 로컬 DB 재생성 → `GroupMapper.deleteSubmissionGuessesByGroupId`, `WithdrawMapper` 의 추측 삭제, 관련 테스트 삭제. (이 경우 결정 표에 "G 유형 잔재 삭제: 예" 를 추가하고 계획을 요청할 것.)

## 재개 조건

음성을 되살리거나, 사람이 정답을 맞히는 새 틀(예: R 유형 `DRAW_GUESS`)을 도입하기로 하면 이 문서의 이전 설계(정답 정규화·3회 시도·행 잠금·`answer` 공개 조건·별칭 비노출 SELECT 제외)를 이전 버전(커밋되지 않은 복사본 `.agent/queue/B6-guess-templates.md` 가 남아 있으면 거기, 없으면 이 문서 하단 요약)에서 복원해 새 계획으로 쓴다. 요약: 정답/별칭 정규화는 NFC→공백 제거→소문자, 시도는 최대 3회, `SELECT … FOR UPDATE` 로 제출 행 잠금, `answer` 공개는 작성자 본인·맞힌 사람·마감 후, `answer_aliases` 는 응답에 절대 SELECT 하지 않음.
