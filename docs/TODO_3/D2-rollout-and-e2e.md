# D2. 롤아웃 절차, 드라이런, 테스트넷 E2E

> 범위: 절차·검증·소규모 코드(앱의 탐색기 링크 활성화 확인 등). **선행: C4, D1, A6**(B2/B3 완료 가정). 근거: `BLOCKCHAIN_BADGES.md` §13·§14·§15, 결정 10. 

## Goal

업적 기능을 **위험을 단계적으로 줄이며** 켠다: ① 체인 없이 출시(`ISSUED_OFFCHAIN`) → ② 드라이런으로 판정 검증 → ③ 소급 → ④ 테스트넷 연동 → ⑤ 장애 주입·E2E 검증. 각 단계의 통과 기준과 되돌리는 방법을 문서화하고 실제로 한 번 수행한다.

## Findings

- 스위치들: `hawe.badge.enabled`(A3, 기본 false), `hawe.badge.dry-run`(A3), `hawe.badge.backfill.*`(A5), `hawe.chain.enabled`(A1/C1, 기본 false), `hawe.chain.worker.*`(C3), `hawe.chain.address-allocator`(C2). 켜는 순서가 결과를 좌우한다.
- 오발급 정정은 `burn` + 재판정이며 소각도 온체인 기록으로 남는다(BLOCKCHAIN_BADGES.md §13) → **체인을 켜기 전에 판정 정확도를 충분히 검증**하는 것이 핵심 방어다.
- 테스트넷은 초기화·중단될 수 있다. 시연·학습 목적임을 사용자에게 과장하지 않는다.
- 탐색기에서 이미지·이름을 보려면 메타데이터 URL(B3)이 공개 접근 가능해야 한다(배포된 서버 도메인 필요).

## Key Implementation Points

1. **롤아웃 단계표**(문서화 + 각 단계 통과 기준):
   | 단계 | 설정 | 통과 기준 | 되돌리기 |
   |---|---|---|---|
   | 1 오프체인 출시 | `badge.enabled=true`, `chain.enabled=false` | 업적 화면에서 획득·진행도 정상, 제출 응답 지연 변화 없음 | `badge.enabled=false` |
   | 2 드라이런 | `badge.dry-run=true` (수여 안 함, 로그/집계만) | A5 드라이런 요약이 기대와 일치(사람이 샘플 20명 대조) | dry-run 해제 |
   | 3 소급 | A5 소급 실행(알림 off) | 수여 수가 드라이런 예측과 일치, 멱등(2회차 0건) | 행 삭제(오프체인 상태일 때만 안전) |
   | 4 체인 연동 | `chain.enabled=true`(테스트넷), 발급 키·컨트랙트 설정 | 신규 1건 `CONFIRMED`, 탐색기에서 확인 | `chain.enabled=false`(큐는 보존, 재개 가능) |
   | 5 기존분 온체인화 | 스위퍼가 `ISSUED_OFFCHAIN → EARNED` 점진 전환 | 잡 `DONE` 증가, `DEAD` 0 | 스위퍼 중지 |
2. **E2E 체크리스트(테스트넷, 실제 수행)**: 컨트랙트 배포(B2) → 서버 설정 → 신규 계정으로 첫 제출 → `FIRST_SUBMISSION` 획득 → 수 분 내 `CONFIRMED` → 앱 업적 화면에서 "블록체인에서 확인" → 탐색기에서 토큰·메타데이터·이미지 확인 → 양도 시도(`transferFrom`)가 revert 되는지 탐색기/스크립트로 확인 → 탈퇴 → 소각 확인.
3. **장애 주입(실환경 보강)**: RPC URL 을 잘못된 값으로 바꿔 서버 재시작 → 제출·피드·도장 정상, 업적은 `EARNED` 로 쌓임 → RPC 복구 후 자동 처리. 발급 키 잔액을 임계 아래로 → 중단/재개. 서버 프로세스 강제 종료 후 재기동 → `SENT` 가 중복 없이 확정.
4. **앱 탐색기 링크**: 서버가 내려주는 `explorerUrl` 이 올바른 체인 탐색기 형식인지(`.../tx/<hash>` 또는 `.../token/<contract>?a=<id>`), Android 외부 브라우저로 열리는지 확인(A6 의 버튼 연동).
5. **성능 기준**: 제출 API p95 가 업적 기능 on/off 에서 유의미하게 늘지 않음을 간단히 측정(수십 건 평균 비교).
6. 결과를 `docs/FEATURE/BLOCKCHAIN_BADGES.md` §14 형식으로 기록하고 실패 항목은 후속 이슈로 남긴다.

## Constraints

- 테스트넷 배포·키·자금은 사용자가 준비한 뒤에만 진행(자동 실행 금지). 메인넷 설정 금지.
- 운영 DB 에서 실행하기 전 백업/드라이런 필수. 소급은 알림 off.
- 키·RPC URL 이 포함된 설정/로그를 보고서·저장소에 남기지 않는다.
- 커밋/푸시 금지.

## Edge Cases

- 드라이런과 실제 수여 결과 불일치 → 원인(규칙 버그, 데이터 경계) 수정 전에는 3단계로 가지 않는다.
- 소급 중 체인이 켜져 있으면 대량 잡 → 소급은 체인 off 상태에서 먼저 끝낸다(순서 4 이전).
- 테스트넷 faucet 한도로 잔액 부족 → 소량부터, 잔액 모니터 동작 확인.
- 도메인/HTTPS 없는 환경에서 탐색기가 메타데이터를 못 읽음 → 이미지 미표시는 알려진 제한으로 기록.
