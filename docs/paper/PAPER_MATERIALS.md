## 1. 논문 주제

**"제출 후 열람" 규칙을 가진 소규모 그룹 일상 공유 앱에서, 서로 다른 위치에 배치한 세 가지 AI(서버 검증형 LLM 미션 생성, 서버 측 사진–주제 적합도 평가, 온디바이스 그림 인식)를 설계·구현한 사례.**

선정 이유:
- 학술대회(인공지능융합기술)의 성격에 맞고, 세 AI 모두 코드와 평가 수치로 설명할 수 있다.
- 단순 "앱 소개"가 아니라 **"생성형 AI를 서비스에 안전하게 넣는 구조"**(서버가 틀을 정함 → LLM은 내용만 → 서버 재검증 → 폴백)라는 설계 논점이 있다.
- 사용자 효과(참여율 향상)는 검증되지 않았으므로 주제에서 제외하고 향후 연구로 둔다.

## 2. 제목 후보

1. **LLM 기반 그룹 맞춤형 미션 생성과 경량 비전 AI 피드백을 적용한 소규모 그룹 일상 공유 앱 개발**
2. 제출 후 열람 구조와 생성형 AI 미션을 적용한 소규모 그룹 일상 공유 모바일 서비스의 설계 및 구현
3. 서버 검증형 LLM 미션 생성과 온디바이스 그림 인식을 활용한 그룹 참여형 모바일 앱 HA'WE

**추천: 1번.**
- 핵심 기술 두 축(LLM 미션 생성 / 경량 비전 AI: CLIP 기반 사진 평가 + int8 CNN 그림 인식)과 서비스 성격(소규모 그룹 일상 공유)을 함께 담는다.
- "개발"로 끝나 구현 중심 논문임을 드러내고, "효과 향상" 같은 검증되지 않은 주장을 포함하지 않는다.
- 2번은 서비스 규칙이 앞에 와서 AI 학회 성격이 약하고, 3번은 사진 평가가 빠지고 서비스명이 홍보처럼 보일 수 있다.

## 3. 연구 배경 및 필요성

- 연인·가족·친구 같은 소규모 그룹은 평소 연락이 뜸해지고, 일상을 먼저 공유하는 데 부담을 느낀다(프로젝트 기획 문제의식). 이를 일반화한 사회적 근거는 문헌으로 보강해야 한다 **[추가 확인 필요 — 외부 인용]**.
- 대화의 계기(주제)를 매일 사람이 만들기 어렵다 → 생성형 AI로 그룹 상황에 맞는 미션을 자동 생성할 필요.
- 그러나 LLM 출력은 형식 오류·중복·부적절한 내용이 생길 수 있고, 그룹 구성원의 개인정보를 외부 AI에 보내는 문제가 있다 → **생성 범위를 제한하고 서버가 검증하는 구조**가 필요.
- 사진·그림 제출물에 즉각적이고 긍정적인 피드백을 주려면 비전 AI가 필요하지만, 대형 모델은 서버 자원·지연이 크고 그림을 외부로 보내는 것은 부담 → **경량화·온디바이스 추론** 필요.

## 4. 연구 목적

1. 제출해야 그룹원의 답을 볼 수 있는 **제출 후 열람 규칙**을 서버 접근 제어로 구현한 소규모 그룹 일상 공유 앱(iOS·Android·Spring Boot)을 개발한다.
2. 서버가 미션 틀을 정하고 LLM은 문장·빈칸만 생성하며, 서버가 형식·중복·금지어를 재검증하고 실패 시 예비 문장으로 대체하는 **신뢰 가능한 미션 생성 파이프라인**을 설계한다. 이때 개인 식별 정보는 LLM에 보내지 않는다.
3. 사진 미션에는 CLIP 기반 **사진–주제 적합도 서비스**를, 그림 미션에는 직접 학습한 **경량 CNN 온디바이스 그림 인식**을 적용해 제출물에 긍정적 AI 피드백을 제공한다.
4. 각 AI 구성 요소를 정량 평가(정확도, ROC-AUC, 모델 크기)하고, 향후 사용자 실험을 위한 비교 실험 구조를 마련한다.

## 5. 연구 내용과 방법 (논문 Ⅱ장 재료)

### 5-1. 시스템 구성
- 클라이언트: iOS(SwiftUI), Android(Kotlin·Jetpack Compose) 네이티브 앱, REST + JWT.
- 서버: Spring Boot 4.1 / Java 25, MyBatis, MariaDB·MySQL(Flyway), 기능별 패키지 구조(controller–service–dao).
- AI: LLM 게이트웨이(Anthropic Messages 형식, 운영은 Amazon Bedrock의 Claude Haiku 계열 [정확한 모델명 추가 확인 필요]), Python 비전 서비스(FastAPI + ONNX Runtime), 기기 내 CNN(LiteRT/Core ML).
- 인프라: AWS EC2 + RDS(MySQL) + S3(비공개, presigned URL).
- 비동기: 트랜잭션 커밋 후 이벤트, 별도 스레드 풀에서 AI 피드백 → 제출 응답이 AI를 기다리지 않음.

### 5-2. 서비스 규칙
- 그룹 관계 5종, 정원(연인 2 / 그 외 6), 초대 코드.
- 그룹이 하루 미션 수(1~5)와 슬롯별 발행·마감 시각 설정. 미션 행에 시각 고정 저장.
- 제출 전 피드 조회 시 서버가 HTTP 423 Locked 반환.
- 도장은 저장하지 않고 제출 기록으로 계산(참잘했어요/지각/벌점).

### 5-3. LLM 미션 생성 파이프라인 (핵심)
1. 스케줄러(매 분) → 발행 시각이 된 슬롯 탐색.
2. 서버가 결정적 시드로 미션 틀 선택(어제와 다른 매체, 같은 날 매체 중복 방지), 필요 시 대상 멤버 지정.
3. LLM 입력: 날짜·요일, 관계, 틀·빈칸 정의, 대상 유무, 최근 미션, 카테고리 목록, 특별한 날, 미션 단위 참여 통계. 이름·그룹명·제출물 제외.
4. 도구 호출 강제로 `{content, category, params}` JSON 수신, 시스템 프롬프트 캐시.
5. 서버 재검증: 항목 구성·길이·카테고리·금지어·틀별 형식(삼행시 3글자 등)·`[대상]` 자리표시자·최근 미션과 bigram 유사도 < 0.8.
6. 실패 시 제한 시간 안 재시도 → 예비 문장 폴백, 출처(AI/AI_FALLBACK/PLACEHOLDER) 기록.
7. 표시 시 `[대상]`을 닉네임으로 치환하고 받침에 맞게 조사 보정.

### 5-4. 사진–주제 적합도 평가
- CLIP ViT-B/32 이미지 인코더 + 다국어 텍스트 인코더, 주제 1개 + 대조 주제(일상 72개/색 10개) softmax → fit(0~1).
- 틀별 임계값(정밀도 95%/85% 기준), 긍정 피드백만 노출, ONNX fp16 서빙.

### 5-5. 온디바이스 그림 인식
- Quick, Draw! 50범주 150만 장, 소형 CNN 146,258 파라미터, 증강(굵기·회전·비율).
- 학습–앱 공통 전처리 명세 + 골든 테스트, int8 양자화 선택 규칙, "잘 모르겠어요" 임계값 0.55.

### 5-6. 부가 기능
- 반응·댓글·멘션·콕찌르기, 알림 목록, 그룹 달력, Nori 형태소 분석 기반 월간 인사이트, AI 마스코트 "별"의 자동 댓글.

## 7. 결론 핵심

- 제출 후 열람 규칙을 서버에서 강제하는 소규모 그룹 일상 공유 앱을 iOS·Android·서버로 구현했다.
- LLM은 "서버가 정한 틀 안에서 내용만" 생성하고, 서버 검증·폴백으로 AI 장애·형식 오류가 서비스 동작을 막지 않게 했다. 개인 식별 정보는 LLM에 보내지 않았다.
- 비전 AI를 위치별로 나눠, 사진은 내부 서버(ONNX fp16)에서, 그림은 기기 안(int8 158KB)에서 처리했고 각각 정량 평가로 임계값을 정했다.
