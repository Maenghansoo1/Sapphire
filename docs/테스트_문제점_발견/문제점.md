# 테스트 중 발견한 문제점

테스트하다 발견한 문제를 여기에 모아 두고, 고칠 때 한꺼번에 반영해요. 새 문제는 아래 형식으로 번호를 이어서 추가해 주세요.

---

## 1. "갤러리 발굴" 미션인데 버튼이 "사진 찍기"라서 카메라로만 올리는 것처럼 보임

- **발견:** 2026-10-16, Android 테스트 (미션 "갤러리에서 가장 최근 웃은 사진을 골라줘")
- **증상:** 갤러리에 있는 사진을 올리라는 미션인데 미션 카드의 버튼이 "사진 찍기"예요. 사진을 새로 찍어야만 하는 것처럼 보여요.
- **결정:** 갤러리 미션은 **앨범에서 고르기와 사진 찍기 둘 다 되게** 해요.

### 원인

앨범에서 고르는 기능은 이미 있어요. 사진 수행 화면 왼쪽 아래의 작은 그림 아이콘이 "앨범에서 고르기" 버튼이에요(Android·iOS 둘 다). 문제는 화면이 이 미션을 다른 사진 미션과 똑같이 보여 준다는 점이에요.

1. **미션 카드 버튼 글자가 항상 "사진 찍기"예요.** 사진 미션이면 틀(template)에 상관없이 같은 글자가 나와요.
   - Android: `missionActionTitle` (`feature/mission/MissionFormat.kt:62`)
   - iOS: `actionTitle` (`Core/Models/TodayMission.swift:5`)
2. **사진 수행 화면은 미션 틀을 몰라요.** 주제 문장만 넘겨받아요. 그래서 갤러리 미션에서도 화면 대부분이 카메라 미리보기이고, 앨범 버튼은 글자 없는 작은 아이콘이라 눈에 잘 안 띄어요.
   - Android: `MissionPerformScreen.kt:31` → `PhotoMissionScreen`
   - iOS: `MissionPerformView.swift:28` → `PhotoMissionView`
3. **화면에 들어가자마자 카메라 권한부터 물어봐요.** 갤러리 미션에서도 마찬가지예요. 권한을 거부하면 "설정에서 카메라 권한을 켜 주세요"가 떠서, 앨범으로 올릴 수 있는데도 막힌 것처럼 보여요. 앨범 고르기에는 권한이 필요 없어요.
4. 앨범에서 사진을 고른 뒤에도 버튼이 "다시 찍기"로 나와요.

### 고칠 방향 (Android·iOS 둘 다)

- 미션 카드 버튼: `PHOTO_GALLERY`이면 "사진 고르기"처럼 고르는 동작이 드러나는 글자로 바꿔요. iOS는 미션 모델에 틀 값이 있는지 먼저 확인해 주세요.
- 사진 수행 화면에 틀 값을 넘겨요. `PHOTO_GALLERY`일 때는 이렇게 바꿔요.
  - "앨범에서 고르기"를 글자가 있는 큰 주 버튼으로 하고, 카메라는 보조로 둬요.
  - 화면에 들어가자마자 카메라 권한을 묻지 않아요. 카메라를 쓰려고 할 때 물어봐요.
  - "다시 찍기"를 "다시 고르기"로 바꿔요.
- 다른 사진 틀(`PHOTO_NOW` 지금 이 순간, `PHOTO_COLOR` 색깔 사냥)은 지금처럼 카메라 위주로 둬요.
  - **결정 필요:** 이 틀에도 앨범 버튼이 있어서 "지금 이 순간" 미션에 예전 사진을 올릴 수 있어요. 이대로 둘지 팀에서 정해 주세요.

### 서버

수정할 것은 없어요. `PHOTO_GALLERY`는 원래 갤러리에서 사진을 찾는 틀이에요(`MissionTemplate.java:7`, `docs/FEATURE/MISSIONS.md`의 "갤러리 발굴"). 이번 미션 문구는 AI를 연결하지 않았을 때 쓰는 예시 문구예요(`PlaceholderMissionGenerator.java:43`).

### 확인 방법

개발자 모드 → 개발자 도구 → 미션 생성에서 `PHOTO_GALLERY`를 고르면 같은 상황을 바로 만들 수 있어요.

## 2. "A를 B로" 그림 미션: 문장 문법 오류 + 뜻이 안 전해짐 + AI 판정이 틀린 것처럼 보임

- **발견:** 2026-10-19, Android 테스트 (미션 "구름을 풍선로 바꿔 그려줘", 템플릿 `DRAW_A_TO_B`)
- **증상:** 문장이 "풍선로"로 틀렸고, 무엇을 그리라는 건지 이해가 어려움. 그림을 그리자 AI 추측이 "구름 100%"인데 결과가 "AI가 못 맞혔어요"로 나옴.

### 2-1. 문장 문법 오류 (서버)

- AI가 꺼져 있을 때 쓰는 예비 문장이 받침을 보지 않고 조사를 붙여요.
  - `PlaceholderMissionGenerator.java:118` `drawTo`: `a + "을 " + b + "로 바꿔 그려줘"` → "풍선**로**"(→ 풍선**으로**), 받침 없는 단어면 "고양이**을**"(→ 고양이**를**)
  - `PlaceholderMissionGenerator.java:114` `sketch`: `subject + "을 30초 안에 그려줘"` → 같은 문제
- **고칠 방향:** 받침에 따라 을/를, 으로/로를 고르는 작은 함수를 서버에 두고 두 곳에 써요. Android `core/KoreanText.kt`의 `josa`와 같은 규칙이에요(ㄹ 받침은 "로").
- AI가 켜져 있으면 AI가 문장을 직접 써서 이 문제는 거의 없어요. AI가 꺼졌거나 실패했을 때만 나와요.

### 2-2. 미션 뜻이 안 전해짐 (앱)

- "A를 B로"는 **A를 B처럼 보이게 바꿔서 그리기**예요(`docs/FEATURE/MISSIONS.md`). 화면에는 문장 하나뿐이라 처음 보면 헷갈려요.
- **고칠 방향:** 밸런스 게임·한 줄 후기처럼 안내 한 줄을 추가해요. 예: "구름을 풍선 모양으로 상상해서 그려요". Android는 `templateGuideText` (`feature/mission/MissionFormat.kt:70`)에 `DRAW_A_TO_B`를 추가하고, iOS도 같은 문구를 넣어요.

### 2-3. AI 판정이 이 미션과 안 맞음 (앱, A8·iOS 9)

- 앱은 "A를 B로" 미션의 정답을 **B**로 봐요(`feature/draw/DrawSubjectMatcher.kt:36`). 이번에는 정답이 "풍선", AI 추측이 "구름"이라 "못 맞혔어요"가 나왔어요.
- 문제 ①: **A에서 출발한 그림이라 AI가 A를 알아보는 게 자연스러워요.** 지금은 그게 실패처럼 보여요.
- 문제 ②: **AI 모델에 '풍선'이 없어요.** '열기구'(hot air balloon)의 다른 이름으로 '풍선'을 넣어 둬서, 보통 풍선을 그리면 거의 맞힐 수 없어요.
- **고칠 방향:**
  - "A를 B로"에서는 **A나 B 중 하나만 알아봐도 맞힌 걸로** 쳐요. 문구는 예를 들어 "AI가 '구름'을 알아봤어요"처럼 바꿔요.
  - '열기구'의 다른 이름 목록에서 **'풍선'을 빼요.** 그러면 '풍선'은 모델에 없는 단어가 돼서, 판정 없이 AI 추측만 보여 줘요(지금 대상 지정 미션처럼).
  - 다른 이름 목록은 세 곳에 똑같이 있어요: `ml/quickdraw/categories.json`(원본), `android/app/src/main/assets/quickdraw/categories.json`, `ios/HAWE/Resources/QuickDraw/quickdraw-categories.json`. 원본을 고친 뒤 두 복사본도 똑같이 맞춰 주세요. Android 테스트(`InkPreprocessorTest.copiesMatchMlOriginals`)가 원본과 복사본이 같은지 검사해요.
  - 모델을 다시 학습할 필요는 없어요(이름 목록만 바뀜).

### 확인 방법

개발자 도구 → 미션 생성에서 `DRAW_A_TO_B`를 골라요. 대상 없는 미션이 나올 때까지 다시 뽑기를 해요.
