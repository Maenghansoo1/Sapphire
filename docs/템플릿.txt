

Project Overview

한 줄 소개
소규모 그룹이 "오늘 서로 어떻게 지내는지"를 부담 없이 나눌 수 있도록, 
매일 정해진 시각에 열리는 관계 맞춤 미션과 제출 데이터 분석, 
이미지 인식 모델을 결합한 앱 서비스입니다.

Problem

- 가까운 사이도 평소엔 연락이 뜸하고, 일상을 먼저 꺼내는 일에 부담을 느끼는 사람이 많음.
- SNS는 남에게 보여 주려고 꾸민 하루가 많아서 가벼운 공유는 오히려 쉽지 않음.

Solution

- 매일 열리는 관계 맞춤 미션 + "먼저 답해야 보이는" 피드
- 부담을 낮추는 가벼운 참여 장치 + AI
- 소규모 그룹 데이터 인사이트 + 앱 공통 정보 위계

Key Experience

- 오늘의 미션: 정해진 시각에 그룹 맞춤 미션이 열림, 무슨 말을 꺼낼지 고민 없이 참여
- AI 사진 적합도: 제출한 사진/그림이 오늘의 미션 주제와 맞는지 AI가 판별
- 그룹 인사이트: 형태소 분석으로 답변 속 키워드/참여패턴을 집계해 한눈에 제공

Design Principles

1. VISUAL HIERARCHY
오늘의 미션 · 제출 버튼 중심의 우선순위

2. CONSISTENCY
전 화면 동일한 UI 규칙 (색상 · 버튼 · 카드)

3. FEEDBACK
Loading / Success / Error 명확화 (제출 완료 시 스탬프 반응)

4. ACCESSIBILITY
대비 · 터치 영역 · 대체텍스트 고려

5. CLEAR LOCK STATE
제출 전 피드 잠금을 이유와 함께 안내

6. PLAYFUL MOTIVATION
스탬프 · 콕찌르기로 부담 없는 참여 유도


System Architecture

구성 한눈에 보기

[Client]  Android / iOS 앱
    │  HTTPS (REST + JWT)
    ▼
[AWS EC2]  Spring Boot 4.1.1 (Java 25)
    ├─ Controller → Service → DAO (MyBatis), 기능별 패키지
    ├─ 스케줄러: 그룹별 미션 발행 / 월말 인사이트 생성
    ├─ 형태소 분석(Lucene Nori) · 집계 · 비동기 처리
    └─ FastAPI 사진 적합도 서비스 (별도 프로세스, 다국어 CLIP)
    │
    ├──▶ [AWS RDS]      MySQL (Flyway 마이그레이션)
    ├──▶ [AWS S3]       제출 사진 · 프로필 이미지 저장
    └──▶ [AWS Bedrock]  LLM 기반 관계 맞춤 미션 생성

(Components)

- Client: 앱에서 가입 · 그룹 · 오늘의 미션 제출 · 피드 열람. "AI가 맞혀볼게요"는 앱 안에서 TFLite / Core ML로 온디바이스 추론 (서버 관여 없음)
- API Server (EC2): Spring Boot 단일 서버. JWT 기반 stateless 인증, MyBatis로 DB 접근
- DB (RDS MySQL): USERS, GROUPS, MISSIONS, SUBMISSIONS 등 핵심 데이터 저장. 스탬프는 별도 저장 없이 제출 기록 유무로 계산
- Storage (S3): 이미지는 S3에 저장하고 DB에는 경로만 보관 (개발 환경은 로컬 파일 시스템)
- AI (Bedrock): 그룹 관계에 맞는 오늘의 미션 문구 생성
- Vision Service (FastAPI): 제출 사진이 미션 주제와 맞는지 점수 산출, 판정 임계값은 백엔드에서 적용
- Scheduler: 그룹별 발행 시각에 오늘의 미션을 자동 오픈

(Key Flows)

1. 미션 발행: 스케줄러가 발행 시각에 Bedrock으로 미션을 생성하고 RDS에 저장
2. 미션 제출: 앱 → API 서버 → 사진은 S3, 기록은 RDS 저장 → Vision Service가 적합도 판별
3. 피드 열람: 제출 여부 확인 후 열람 허용, 미제출 시 423 Locked 응답
4. 그룹 인사이트: 닫힌 미션의 답변을 서버 내부에서 형태소 분석 후 집계 (외부로 본문 전송 없음)

(Deployment & Security)

- 배포: EC2 (API 서버 + Vision Service), RDS (MySQL), S3, Bedrock
- 보안: RDS는 EC2 보안 그룹에서만 접근, S3는 비공개 버킷 + 서버 발급 접근, 개인 콘텐츠는 인사이트 · 외부 API로 전송하지 않음
- DB 엔진: 현재 MariaDB에서 MySQL로 교체 예정 (Flyway 마이그레이션 SQL의 호환성 확인 필요)
- 제외 범위: 푸시 알림(FCM)은 2차 범위

Key UI / Feature Flow

01 오늘의 미션 확인
오늘의 미션 카드 + 그룹 진행 현황 (미제출 시 피드는 잠금 상태로 표시)

→ 02 미션 제출
사진 · 글 · 그림 중 미션 방식에 맞춰 제출 (제출 버튼 중심 화면)

→ 03 제출 결과
AI 사진 적합도 피드백 + "참잘했어요" 스탬프 (Loading / Success / Error 즉시 표시)

→ 04 그룹 피드 열람
잠금 해제 후 멤버 글 보기 · 반응 · 댓글, 미제출 멤버에게 콕찌르기

핵심 Task를 4단계로 단순화하고, 각 단계의 상태 변화가 즉시 보이도록 Feedback을 설계했습니다.

Challenge → Fix

01
문제: 한국어 미션 주제와 제출 사진이 맞는지 판별하기 어려움
해결: 다국어 CLIP에 한국어 주제를 직접 입력하고, 판정은 백엔드 임계값으로 분리 (낮은 점수는 표시하지 않음)

02
문제: 답변 속 조사 · 불용어 때문에 키워드 집계가 왜곡됨
해결: 형태소 분석(Lucene Nori)으로 명사만 추출 + 불용어 제거 + 한 제출 내 중복 1회 집계

03
문제: 그림 인식을 서버에서 처리하면 지연이 생기고 개인 그림이 외부로 전송됨
해결: Quick, Draw! 데이터로 CNN 직접 학습 · 경량화 후 TFLite / Core ML 온디바이스 추론


Implementation Highlights

· 미션 생성      Bedrock LLM으로 그룹 관계에 맞는 오늘의 미션 문구 생성
· 사진 적합도    다국어 CLIP 점수 + 백엔드 임계값으로 미션 주제 일치 여부 판별
· 그룹 인사이트  Nori 형태소 분석으로 명사 키워드 집계, 결과는 캐시 + 비동기 생성
· 온디바이스 AI  Quick, Draw! 학습 CNN을 TFLite / Core ML로 앱 안에서 추론
