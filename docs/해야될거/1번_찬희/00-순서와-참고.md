## 다른 사람과 주고받는 지점

- **B10 은 둘이 나눠서 한다.** 우준이 Python 비전 서비스(`ml/vision-service/`, Key Points 1~6, 정확도 평가)를 먼저 만들고, 찬희가 Spring 연동(Key Points 7~15)을 한다. 둘 사이 약속은 계획에 적힌 `POST /v1/topic-fit` 하나뿐이다.
- **`SubmissionService` 를 고치는 순서**: B0(우준) → B1(찬희) → B5(우준) → B10 연동(찬희) → B4(찬희). 앞 사람이 커밋·푸시했다는 연락을 받고 시작한다.
- 앱 작업이 기다리는 것: 경환 A3 ← B1·B2·B3(완료), **우준 A7 ← B10 연동**(2026-10-13 A4·A7 을 우준이 가져감), 경환 A9 ← B11. 끝나면 바로 알려 준다.

## 겹치는 파일 주의

- `GroupService`/`GroupMapper`: 우준의 **B7**(그룹 목록 `todayMissions`, 멤버 지표)도 고친다. B7 시작 전에 서로 말하고, 고치는 사람은 시작 직전 pull·끝나자마자 push.
- `SecurityConfig`: 우준의 **B9**(`/internal/**` 열기)가 한 줄 고친다.
- `V1__initial_schema.sql`: 우준의 **B9** 도 `missions` 에 컬럼을 추가한다. V1 을 고칠 때마다 단톡에 알리고 모두 로컬 DB 를 다시 만든다.
- **B12** 는 우준의 B8/B9 영역(`MissionAiProperties`, `AiMissionGenerator`, `AnthropicClient`)을 고친다. 시작 전에 우준과 말하고, 팀원 프롬프트 파일(저장소 밖)은 건드리지 않는다. `pom.xml`(Spring AI BOM)과 `application.properties` 도 바뀐다.
- B1 과 B0 를 동시에 할 때: B0 는 `SubmissionService`/`SubmissionResponse`, B1 은 `SubmissionMapper`/`SubmissionRow`/`CommentMapper` 를 주로 고쳐 겹침이 적다. 먼저 끝난 쪽이 바로 push.

## 진행 방법 (3명 공통)

1. 시작 전에 `git pull`. 앞 단계 담당자의 커밋이 들어왔는지 확인.
2. 계획 파일 내용을 `.agent/plan.md` 에 복사해 AI(Codex/Claude)에게 맡기거나, Claude Code 에서 계획 파일을 직접 읽혀 진행.
3. 보고서·리뷰 후 **바로 커밋·푸시**하고 단톡에 "B○ 끝" 알림. 커밋 메시지는 팀 형식 `type(scope): 내용` (예: `feat(group): 그룹 내 프로필 API`).
4. V1 을 고쳤으면 단톡에 알리고, 다른 사람은 pull 후 로컬 DB 를 비우고 다시 만든다.
5. 테스트: `.\mvnw.cmd clean test -q`. 계획 파일 안의 JDK 경로는 각자 PC 에 맞게 바꿔 쓴다.
