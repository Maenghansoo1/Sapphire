# A11. 사진 얼굴 자동 모자이크 (사용자 선택) (Android)

> 범위: Android 앱만(서버 변경 없음). 작성 2026-11-09. iOS 이식은 경환(아래 "iOS 넘김").
>
> **목표 한 줄**: 사진을 올리기 전에 사용자가 원하면 **휴대폰 안에서 얼굴을 찾아 모자이크**한다. 어떤 얼굴을 가릴지는 사용자가 고르고, 못 찾은 부분은 손으로 직접 가릴 수 있다. **원본 사진은 휴대폰 밖으로 나가지 않는다.**

## Goal

- 사진 미션(갤러리, 지금 이 순간, 색깔 사냥)에서 사진을 고르거나 찍은 뒤 **[얼굴 가리기]** 를 켜면 얼굴마다 모자이크가 미리 보인다.
- 얼굴을 눌러 하나씩 가리기·풀기를 할 수 있다.
- 못 찾은 얼굴이나 다른 개인정보(이름표, 번호판 등)는 손가락으로 네모를 그려 직접 가린다.
- [올리기] 를 누르면 **모자이크가 적용된 사진만** 업로드된다.
- 기본은 꺼짐(사용자 선택 기능).

## Findings (2026-11-09 코드 기준)

- 사진 화면: `feature/mission/PhotoMissionScreen.kt`. 갤러리 미션은 앨범에서, 찍는 미션은 카메라에서 사진을 받아 `photo: Bitmap` 상태로 미리 본 뒤 [올리기].
- 사진 불러오기: `feature/mission/PhotoProcessing.kt` `loadCroppedPhoto`(27줄) — EXIF 회전을 반영해 **똑바로 세운 뒤** 3:4로 자른다. 그래서 얼굴 인식에 넘길 때 회전 처리를 따로 안 해도 된다.
- 업로드 바이트: 같은 파일 `photoJpegBytes`(63줄) — 비트맵을 JPEG 로 다시 압축 → 원본 EXIF(위치 등)는 따라가지 않는다(확인 필요, 아래 단계).
- 앱에는 아직 ML Kit 의존성이 없다. 라이선스 화면은 `feature/mypage/LicensesScreen.kt`.
- 사진 AI(서버 CLIP)는 업로드된(=모자이크된) 사진을 분석한다. 사람 얼굴이 주제인 미션은 점수가 조금 낮아질 수 있다(문서에 적어 둔다).

## Key Implementation Points

1. **얼굴 찾기 도구**: Google ML Kit 얼굴 인식(무료, 기기 안). 두 가지 중 하나를 고른다.
   - 앱에 모델을 넣는 방식(`com.google.mlkit:face-detection`): 바로 동작, 앱 크기 증가
   - Google Play 서비스가 모델을 받는 방식(`play-services-mlkit-face-detection`): 앱 크기 작음, 처음에 모델 다운로드 필요
   → 1단계에서 앱 크기 증가를 재고 정한다. 이용 약관을 확인하고 라이선스 화면에 적는다.
2. **모자이크 계산은 순수 함수로**: 픽셀 배열(IntArray)과 사각형 목록을 받아 블록 단위로 평균색을 칠한다. 안드로이드 없이 단위 테스트가 가능해야 한다(`InkPreprocessor` 방식).
   - 블록 크기는 얼굴 크기에 비례(작은 얼굴도 알아볼 수 없게 최소 블록 수 보장).
   - 얼굴 상자를 사방으로 20% 넓혀서 머리카락·턱까지 가린다.
3. **선택 상태**: 찾은 얼굴 목록 + 각 얼굴 가림 여부 + 손으로 그린 네모 목록. 순수 Kotlin 상태 클래스로 만들고 테스트한다.
4. **원본 보호**: 업로드는 항상 "모자이크를 적용한 새 비트맵"으로 한다. 원본 비트맵은 업로드 후 메모리에서 버린다. 얼굴 위치 정보는 저장·전송하지 않는다.

## Implementation Steps

**준비·결정**
1. `git pull`, 커밋 안 한 작업 정리.
2. ML Kit 두 방식(앱 포함 vs Play 서비스) 각각 넣어 보고 APK 크기 증가 측정.
3. 이용 약관·라이선스 확인, 방식 결정(보고서에 크기와 이유 기록).
4. `photoJpegBytes` 결과에 EXIF(특히 위치)가 남지 않는지 실제 파일로 확인. 남으면 지우는 처리 추가.

**모자이크 (순수 함수)**
5. `Mosaic.kt`: `pixelate(argb, width, height, rects, blockSize)` 구현.
6. 얼굴 크기에 맞는 블록 크기 계산 함수(`blockSizeFor(rect)`).
7. 상자 넓히기 + 사진 밖으로 나가지 않게 자르기 함수.
8. 단위 테스트: 가린 영역 안은 블록마다 한 색, 밖은 원래 그대로, 사진 가장자리 얼굴, 겹치는 상자, 아주 작은 얼굴.

**얼굴 찾기**
9. `FaceFinder` 래퍼: `suspend fun find(bitmap): List<Rect>` (ML Kit 호출, 백그라운드 스레드).
10. 설정: 정확도 우선 모드, 최소 얼굴 크기(너무 작은 얼굴도 찾도록 조정해 보고 값 기록).
11. 실패·시간 초과 처리(찾기 실패 → "얼굴을 찾지 못했어요. 직접 가릴 수 있어요").
12. 계측 테스트: 공개 저작권 없는(퍼블릭 도메인) 얼굴 사진 몇 장을 테스트 자료로 넣고 얼굴을 찾는지 확인.

**선택 상태**
13. `FaceBlurState`: 얼굴 목록, 얼굴별 가림 여부(기본 전부 가림), 손으로 그린 네모 목록, 되돌리기.
14. 단위 테스트: 얼굴 하나 풀기, 다시 가리기, 네모 추가·삭제, 전체 끄기.

**화면**
15. 사진 미리보기 아래에 [얼굴 가리기] 스위치(기본 꺼짐).
16. 켜면 얼굴 찾기 → 미리보기에 모자이크 표시(찾는 동안 로딩 표시).
17. 미리보기에서 얼굴을 누르면 그 얼굴만 가리기/풀기.
18. [직접 가리기] 모드: 손가락으로 네모를 그려 추가, 길게 누르면 삭제.
19. 안내 문구: "가린 사진만 올라가요. 원본은 휴대폰 밖으로 나가지 않아요."
20. 접근성: 얼굴마다 "얼굴 1, 가림" 같은 설명.

**업로드 연결**
21. [올리기] 할 때 스위치가 켜져 있으면 모자이크를 적용한 비트맵으로 `photoJpegBytes` 호출.
22. "다시 찍기/다시 고르기"를 누르면 상태 초기화.
23. 업로드 뒤 원본 비트맵 참조 정리(메모리).

**확인**
24. 수동 확인 목록: 여러 명 단체 사진, 옆모습, 작은 얼굴, 얼굴 없는 사진, 어두운 사진, 아주 큰 사진, 갤러리·카메라 둘 다.
25. 사진 AI 점수에 미치는 영향 확인(같은 사진 가림 전·후 점수 비교 몇 장, 문서에 기록).
26. 기존 사진 미션 테스트 통과.

**마무리**
27. 라이선스 화면에 ML Kit 추가.
28. 개인정보 처리방침 초안 문구 추가(얼굴 인식은 기기 안에서만, 결과 저장 안 함) — 팀과 확정.
29. `docs/FRONTEND/ANDROID.md` 기능 설명, iOS 넘김 문서.
30. 커밋·푸시, 계획 파일 이름을 `A11(완료)-...` 로 바꾸기.

## iOS 넘김 (경환)

- 얼굴 찾기: Apple Vision `VNDetectFaceRectanglesRequest`(기기 안, 무료).
- 모자이크: Core Image `CIPixellate` 를 얼굴 영역에만 적용하거나 Android 와 같은 블록 평균 방식.
- 화면 흐름과 문구는 Android 와 같게.

## Edge Cases

- 얼굴을 못 찾음 → 직접 가리기 안내.
- 사람이 아닌 얼굴(인형, 그림 속 얼굴)을 얼굴로 찾음 → 사용자가 눌러서 풀 수 있음.
- 아주 큰 사진 → 이미 `loadCroppedPhoto` 가 줄인 크기 사용.
- 스위치를 켰다 끈 뒤 올림 → 원본 그대로 올라감(사용자 선택).

## Constraints

- 서버로 얼굴 위치·원본을 보내지 않는다.
- 기본값은 꺼짐(사용자 선택 기능).
- 디자인 토큰만 사용.
