# B14. AI 미션 검색: 키워드로 지난 미션 찾기 (Python + 서버 + Android)

> 범위: 비전 서비스(Python)·서버·Android. iOS 화면은 경환(아래 "iOS 넘김"). 작성 2026-11-09.
>
> **목표 한 줄**: 기록 화면에서 "바다", "고양이", "야식"처럼 검색하면 **글자가 똑같지 않아도 뜻이 비슷한** 지난 미션을 AI가 찾아 준다. 예: "야식" → "밤 12시에 먹은 거 찍어 와".

## Goal

- 그룹 멤버가 자기 그룹의 지난 미션을 키워드로 검색한다(다른 그룹은 절대 안 나옴).
- 1단계: **미션 문장**으로 찾는다. 2단계: 내가 볼 수 있는 **제출물**(사진 내용, 글 답, 그림 AI 추측)로도 찾는다.
- 검색 품질을 숫자로 잰다(정답 목록을 만들어 "키워드만 vs AI vs 섞음" 비교).
- 추가 비용 없음: 이미 있는 비전 서비스의 다국어 CLIP(ONNX)을 쓴다.

## Findings (2026-11-09 코드 기준)

- 비전 서비스(`ml/vision-service`)는 사진·글을 같은 공간의 512차원 벡터로 바꾸는 인코더를 이미 갖고 있다(`scoring.py` `OnnxEncoders.texts/image`, 170줄). 지금 API 는 `POST /v1/topic-fit` 하나뿐이라 벡터를 밖으로 주는 API 를 추가해야 한다.
- **주의**: 지난 평가(`ml/vision-service/scoring.py` 머리말, `EVAL.md`)에서 이 모델의 한국어 글 벡터끼리는 관계없어도 유사도 0.9 이상이 흔했다. → **유사도 원래 값으로 자르면 안 되고**, 순위나 보정한 점수를 써야 한다. 키워드 검색과 섞는 게 안전하다.
- 미션 문장은 `missions.content`. 대상 미션은 `[대상]` 이 들어 있고 화면에 보일 때 닉네임으로 바뀐다(`MissionService.displayContent`, 153줄).
- 그룹 멤버 확인: `members.existsByGroupIdAndUserId`. 제출물 잠금: 그 미션에 **내가 제출해야** 남의 제출물을 볼 수 있다(`SubmissionService.requireSubmitted`, 209줄). 검색도 이 규칙을 지켜야 한다.
- 그림 제출에는 AI 추측(상위 3개 이름)이 마스코트 댓글 정보로 저장된다(`MascotService.commentDrawGuess`) → 그림도 이름으로 찾을 수 있다.
- Lucene Nori(형태소 분석)가 이미 의존성에 있다(인사이트, `NoriKeywordExtractor`) → 키워드 검색에 재사용.
- DB 변경 파일은 V4(`V4__ai_mascot.sql`)까지 있다 → 이 작업은 다음 번호(V5 또는 그때 비어 있는 번호).

## Key Implementation Points

1. **비전 서비스에 벡터 API 추가**: `POST /v1/embed/text`(글 여러 개 → 벡터들), `POST /v1/embed/image`(사진 → 벡터). 응답에 모델 이름·버전 포함(모델이 바뀌면 다시 계산하려고).
2. **벡터 저장**: 새 테이블 `mission_embeddings(mission_id, model_version, vector BLOB, created_at)`. 512개 float32 = 2KB. MariaDB/MySQL 에 벡터 전용 타입이 없으므로 바이트로 저장하고 서버에서 비교한다. 그룹 하나의 미션은 많아야 수천 개라 전부 비교해도 빠르다.
3. **언제 계산하나**: 미션이 발행될 때(`MissionsPublishedEvent`) 비동기로 계산·저장. 예전 미션은 한 번에 채우는 작업(백필)으로 처리.
4. **검색 점수 = AI 점수 + 키워드 점수**:
   - AI: 검색어 벡터와 미션 벡터의 유사도를 **그 그룹 미션들 사이의 순위·표준점수로 보정**.
   - 키워드: Nori 로 검색어와 미션 문장의 명사를 뽑아 겹치면 가산.
   - 가중치와 최소 기준은 6단계 평가로 정한다.
5. **권한**: 그룹 멤버만. 제출물로 찾은 결과는 내가 제출한 미션에서만(잠금 규칙).
6. **비전 서비스가 꺼져 있으면** 키워드 검색만으로 동작(검색이 막히지 않게).

## Implementation Steps

**0. 준비**
1. `git pull`, 커밋 안 한 작업 정리.
2. 검색할 대상과 화면 위치를 팀과 확정(기록 캘린더 화면 위쪽 검색창 기본안).

**1. 평가 자료 먼저 만들기 (품질을 숫자로 재기 위해)**
3. 개발자 시드나 팀 테스트 그룹에서 미션 100개 이상 모으기.
4. 검색어 30~50개와 "정답 미션 목록" 만들기(예: "야식" → 미션 3개). 파일: `ml/vision-service/eval-search/queries.json`(개인정보 없게).
5. 평가 스크립트 `eval_search.py`: Recall@5(정답이 상위 5개에 들었나), MRR(첫 정답 순위) 계산.
6. 기준선 측정: 글자 포함(LIKE) 검색, Nori 명사 검색.

**2. 비전 서비스 벡터 API (Python)**
7. `POST /v1/embed/text`: 글 1~64개 → 정규화된 벡터들(base64 float32). 길이 제한·빈 글 검사.
8. `POST /v1/embed/image`: 사진 → 벡터(기존 `clip_pixels` + 사진 인코더 재사용).
9. 응답에 `model`, `version`(fp16 이면 `1-fp16`) 포함.
10. pytest: 형식, 길이 제한, 같은 입력 같은 결과, 오류 응답.
11. README 에 API 추가.

**3. AI 검색 품질 확인 (서버 만들기 전)**
12. `eval_search.py` 에 AI 검색 추가: 검색어·미션 문장을 벡터로 바꿔 유사도 순위.
13. 보정 방식 비교: 원래 유사도 vs 그룹 내 표준점수 vs 순위.
14. 섞기 비교: AI만 / 키워드만 / 섞음(가중치 몇 가지). 결과를 `EVAL_SEARCH.md` 에 기록.
15. 결과가 키워드만보다 나쁘면 여기서 멈추고 방법 다시 정하기(예: 검색어를 "~ 사진", "~ 하기" 문장 여러 개로 늘려 평균 — 색깔 사냥에서 효과 있었던 방식).

**4. DB (서버)**
16. `V5__mission_embeddings.sql`(번호는 그때 확인): `mission_embeddings` 테이블, 미션 삭제 시 함께 삭제.
17. 매퍼: 저장, 그룹 미션 벡터 목록 조회, 모델 버전별 개수.
18. 팀에 새 DB 변경 파일 알림(기존 V1 수정이 아니라 새 파일이라 DB 재생성은 불필요).

**5. 벡터 계산·저장 (서버)**
19. `VisionClient` 에 벡터 API 호출 추가(HTTP/1.1 그대로).
20. 미션 발행 이벤트를 받아 비동기로 문장 벡터 저장(실패해도 발행에 영향 없음, 재시도 1번).
21. `[대상]` 은 닉네임으로 바꾸지 않고 "친구"로 바꿔서 계산(닉네임이 벡터에 섞이지 않게, 같은 미션은 같은 벡터).
22. 백필 작업: 벡터가 없는 미션을 일정 개수씩 채우는 개발자용 API 또는 시작 시 작업.
23. 모델 버전이 바뀌면 다시 계산하는 경로.

**6. 검색 API (서버)**
24. `GET /api/groups/{groupId}/missions/search?q=...&limit=20`.
25. 멤버 확인, 검색어 길이 제한(1~30자), 요청 수 제한 검토.
26. 검색어 벡터 계산(같은 검색어는 잠깐 캐시).
27. 그룹 미션 벡터와 비교 → 보정 → 키워드 점수 섞기 → 정렬.
28. 응답: 미션 id, 날짜, 틀, 화면용 문장(`[대상]` 바뀐 것), 내가 제출했는지, 찾은 이유(키워드 일치·AI 유사).
29. 비전 서비스가 꺼져 있으면 키워드만으로 응답.
30. 테스트: 다른 그룹 미션이 절대 안 나옴, 멤버 아님 403, 키워드만 경로, 정렬, 빈 결과.

**7. 제출물로도 찾기 (2단계)**
31. 사진 제출: 사진 AI 분석 때 이미 계산하는 사진 벡터를 저장(`submission_embeddings`).
32. 글 제출(삼행시, 한 단어 일기 등): 글 벡터 저장.
33. 그림 제출: AI 추측 이름(마스코트 댓글 정보)을 키워드로 사용.
34. 검색 결과에 "누가 올린 사진에서 찾았는지" 표시 — **내가 제출한 미션만**.
35. 평가 다시 실행(제출물 포함 전·후 비교).

**8. Android 화면**
36. 기록(캘린더) 화면 위에 검색창.
37. 입력이 멈추고 300ms 뒤 검색(디바운스), 이전 요청 취소.
38. 결과 목록: 날짜, 미션 문장, 찾은 이유 표시, 누르면 기존 결과 화면으로 이동.
39. 빈 결과·오류·로딩 상태.
40. 최근 검색어(기기 안 저장, 지우기 가능).
41. 단위 테스트(검색 상태), 수동 확인.

**9. 마무리**
42. `docs/BACKEND/API_DESIGN.md` 에 검색 API, `ml/vision-service/README.md` 에 벡터 API.
43. Postman 요청 추가.
44. iOS 넘김 문서, 커밋·푸시, 계획 파일 이름을 `B14(완료)-...` 로.

## Edge Cases

- 한 글자 검색어, 특수문자, 아주 긴 검색어.
- 미션이 거의 없는 새 그룹(결과 없음 안내).
- 벡터가 아직 없는 미션(키워드로만 나옴).
- 그룹을 나간 사람의 제출물, 탈퇴한 사람.
- 30초 스케치·슬라이더처럼 지금은 안 나오는 예전 틀의 미션도 검색돼야 함.

## Constraints

- 다른 그룹 데이터 노출 금지, 잠금 규칙 준수.
- 외부 AI 호출 없음(우리 비전 서비스만).
- 비전 서비스가 없어도 검색은 동작(키워드).

## Tests Required

- Python: 벡터 API pytest.
- 서버: 매퍼(실제 DB), 검색 서비스(권한·정렬·폴백), 컨트롤러 검증.
- 품질: `eval_search.py` 결과 기록(Recall@5, MRR).
- Android: 검색 상태 단위 테스트.
