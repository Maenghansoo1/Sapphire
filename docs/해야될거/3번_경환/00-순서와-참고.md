## iOS (`A5-ios-port.md`) — Mac 필요

- A5 는 Android 결과를 iOS 로 옮기는 **묶음 계획**이다. 항목 0~10 을 Android 해당 단계가 끝날 때마다 하나씩 옮긴다(항목 0 = A0, 2 = A1, 4 = A2, 5 = A3, 6 = A4, 8 = A7, 9 = A8, 10 = A9, 7 = A6).
- **항목 1(10단계 달력·활동 요약)은 이미 코드가 있다**(우준 커밋 `6b0ad46 10단계 ios 적용완료`). Windows 에서 작성해 **Mac 빌드 확인만 남았다** — A5 문서에는 "보류"로 적혀 있지만 실제로는 빌드 확인만 하면 된다.
- Windows 에서는 컴파일이 안 된다. Mac 에서 `xcodegen generate` 후 빌드·실행 확인. Mac 이 없으면 팀에서 Mac 있는 사람과 조율.

## 다른 사람과 주고받는 지점

- 서버 작업이 끝났다는 연락(단톡)을 받고 해당 A 를 시작한다: A3 ← 찬희(B1·B2·B3), A4 ← 우준(B5), A7 ← B10, A8 ← 우준(M1), A9 ← 찬희(B11), A6 ← 우준(B7).
- 기다리는 동안 할 수 있는 것: iOS 이식(A5 항목 0·1·2·4), Figma 가 나오면 임시 이미지(`*_temp`, `stamp_*`) 교체.
- **A4 가 끝나 배포되기 전에는 서버에서 새 틀을 켜면 안 된다**(구 앱이 새 틀을 못 그림). 끝나면 우준에게 알린다.
- A2 참고: 우준 PC 의 로컬 브랜치 `backup/step8-kang` 에 프로필 편집·사진·탈퇴 앱 연결 초안(Android·iOS)이 있다. 필요하면 우준에게 푸시를 부탁해 참고한다(그룹 내 프로필 부분은 B1 계약과 다르니 쓰지 않는다).

## 겹치는 파일 주의

- 서버와는 디렉터리가 달라 충돌하지 않는다. 다만 **문서**(`docs/FRONTEND/*`, `PROJECT_OVERVIEW.md`)는 다른 사람도 고치니 pull 후 작업.
- A 계획끼리는 `DataStore.kt`, `MainNavigation.kt`, `MissionScreen.kt`, `ResultsScreen.kt`, `HIcon.kt` 가 계속 겹친다 → 위 순서를 지키고 하나 끝날 때마다 커밋.

## 진행 방법 (3명 공통)

1. 시작 전에 `git pull`. 기다리던 서버 작업 커밋이 들어왔는지 확인.
2. 계획 파일 내용을 `.agent/plan.md` 에 복사해 AI(Codex/Claude)에게 맡기거나, Claude Code 에서 계획 파일을 직접 읽혀 진행.
3. 보고서·리뷰 후 **바로 커밋·푸시**하고 단톡에 "A○ 끝" 알림. 커밋 메시지는 팀 형식 `type(scope): 내용` (예: `feat(android): 콕 찌르기 연결`).
4. 테스트: `android\gradlew.bat :app:testDebugUnitTest`. JDK 21 이 필요하다 — 계획 파일의 경로(`C:\Users\kimch\...`)는 찬희 PC 기준이니 각자 PC 의 JDK 21(예: Android Studio 의 `jbr` 폴더)로 바꿔 쓴다.
5. 서버 쪽 V1 이 바뀌었다는 알림을 받으면 로컬 DB 를 비우고 다시 만든 뒤 서버를 켠다.
