# 그림 전처리 명세 (학습 ↔ 앱 공통 계약)

학습(`rasterize.py`)과 앱(Android A8, iOS A5)이 **똑같이** 구현해야 하는 규칙이다. 둘이 조금이라도 다르면 학습 때 정확도가 높아도 앱에서는 엉뚱하게 맞힌다.
앱 구현은 `golden/` 의 정답 예시로 검증한다(아래 "검증").

버전: 1 (2026-10-12). 이 문서를 바꾸면 모델을 다시 학습하고 `golden/` 을 다시 만들고 앱에 알린다.

## 전체 흐름

```
그림 → (1) 잉크 마스크(w×h, 참/거짓) → (2) 너무 비었는지 확인 → (3) 잉크 경계 상자로 자르기
     → (4) 정사각형 가운데에 놓기 → (5) 20×20 으로 면적 평균 축소/확대 → (6) 가장 진한 값을 1로 맞추기
     → (7) 28×28 가운데(여백 4)에 놓기 → 모델 입력 [1, 28, 28, 1] float32
```

## 상수

| 이름 | 값 | 뜻 |
|---|---|---|
| `OUTPUT_SIZE` | 28 | 모델 입력 한 변 |
| `BOX_SIZE` | 20 | 그림이 들어가는 칸 한 변 |
| `MARGIN` | 4 | 바깥 여백 (`(28 − 20) / 2`) |
| `MIN_INK(w, h)` | `max(3, ceil(w × h / 2000))` | 잉크 칸 수가 이보다 적으면 "너무 비어 있음" |
| `INK_MIN_ALPHA` | 128 | RGBA 에서 이 값 이상이어야 잉크 후보 |
| `INK_MAX_CHANNEL` | 235 | RGBA 에서 `min(R, G, B)` 가 이 값 **미만**이면 잉크 |

정수 계산: `ceil(w × h / 2000)` = `(w × h + 1999) / 2000` (정수 나눗셈).

## (1) 잉크 마스크 만들기

결과는 `w × h` 크기의 참/거짓 배열이다. 해상도는 자유(그림판 크기 그대로 써도 된다).

**RGBA 이미지에서** (앱의 두 경우 모두 이 규칙 하나로 처리):

```
잉크(x, y)  ⇔  A ≥ 128  그리고  min(R, G, B) < 235
```

| 경우 | 처리 |
|---|---|
| 내가 방금 그린 그림 | 획을 **투명 배경 + 검정 잉크**로 렌더(지우개 적용 후, 색은 무시) → 위 규칙 |
| 결과 화면의 PNG (흰 배경 + 색 잉크) | PNG 를 그대로 디코드 → 위 규칙 |

예: 흰색(255,255,255) 아님 · 투명 검정(A=0) 아님 · 검정 잉크 · 팔레트의 연노랑 `#F2D74E`(min=78) 잉크 · 거의 흰색(240,240,240) 아님.

**학습 데이터에서**: Quick, Draw! 의 획 좌표를 흑백 캔버스에 그린 뒤 `값 > 127` 을 잉크로 한다(`rasterize.py` `render_strokes`).

## (2) 너무 비었는지 확인

잉크 칸 수가 `MIN_INK(w, h)` 미만이면 **여기서 멈추고 추론하지 않는다**(앱은 "조금 더 그려 볼까요?" 안내).

## (3) 경계 상자로 자르기

잉크가 있는 가장 왼쪽·오른쪽 열 `x0, x1` 과 가장 위·아래 행 `y0, y1` 을 구한다(양 끝 포함).
`bw = x1 − x0 + 1`, `bh = y1 − y0 + 1`. 그 사각형만 잘라 0/1 실수 배열로 쓴다. → 그림 위치(이동)가 사라진다.

## (4) 정사각형 가운데에 놓기

`S = max(bw, bh)`. `S × S` 크기의 0 배열 안에, 왼쪽 위 `(ox, oy) = (floor((S − bw) / 2), floor((S − bh) / 2))` 위치에 잘라 낸 그림을 놓는다. → 가로·세로 비율이 유지된다.

## (5) 20×20 으로 면적 평균 (줄이기·늘리기 공통)

원본 한 변 `S`, 결과 한 변 `20`. 결과 칸 `i` 는 원본 구간 `[i × S / 20, (i + 1) × S / 20)` 을 덮는다.
가중치 `W[i][k]` = 그 구간과 원본 칸 `[k, k + 1)` 이 겹치는 길이 ÷ `(S / 20)`. (한 행의 가중치 합 = 1)

```
small[i][j] = Σ_y Σ_x  W[i][y] × W[j][x] × square[y][x]
```

- 가로·세로에 같은 `W` 를 쓴다(정사각형이므로).
- 구간 경계는 `i × S / 20` 을 실수(배정밀도)로 계산한다. 정수 비율이 아니어도(예: S = 37) 같은 식이다.
- 그림이 20칸보다 작으면(S < 20) 늘어나고, 크면 줄어든다. 따로 처리하지 않는다.
- 블러 등 다른 필터는 **쓰지 않는다.**

## (6) 가장 진한 값을 1로

`peak = small 의 최댓값`. `peak > 0` 이면 모든 값을 `peak` 로 나눈다. → 가는 펜으로 그려 흐려진 선도 가장 진한 곳이 1.0 이 된다(펜 굵기 영향 줄이기).

## (7) 28×28 에 놓기

`out` 은 28×28 의 0 배열. `out[4 + i][4 + j] = small[i][j]` (i, j = 0..19).

## 모델 입력

- 값: `float32`, 0.0(빈 곳) ~ 1.0(잉크).
- 순서: 행 우선 `out[y][x]`, y 는 위→아래, x 는 왼쪽→오른쪽.
- TFLite: 텐서 `[1, 28, 28, 1]`(NHWC). Core ML: 같은 의미의 `[1, 28, 28, 1]` 입력(이름은 모델 설명서에 적는다).

## 학습에서만 하는 것 (앱은 하지 않음)

`rasterize.py` 가 학습 그림을 만들 때 앱 그림의 다양함을 흉내 낸다. 전처리 (2)~(7) 은 위와 같다.

- **선 굵기**: 획 좌표(0~255)를 굵기 3~20px 로 그린다(둥근 끝·이음). 앱 펜 3·6·12dp 를 그림 크기 약 100~330dp 에 그렸을 때의 비율(약 1~12%)을 덮는다.
- **회전** ±10°, **가로·세로 따로 늘이기/줄이기** ±10%.
- 이동과 전체 크기 변화는 (3)·(5) 에서 어차피 사라지므로 하지 않는다.

## 검증 (`golden/`)

- `golden/*.json` 하나가 예시 하나다: `{"name", "description", "width", "height", "mask": ["0101…", …], "expected": null 또는 28×28 실수}`.
  - `mask` 는 행마다 문자열 하나, `'1'` = 잉크. `expected` 가 `null` 이면 (2) 에서 멈춰야 한다는 뜻.
- 앱 단위 테스트는 각 `mask` 를 전처리해 `expected` 와 비교한다: **모든 칸의 절대 오차 ≤ 1e-3**, `null` 여부 일치.
- `golden/` 은 `python make_golden.py` 로 만든다. 명세를 바꾸면 다시 만들고 앱에 알린다.

## 알려진 한계

- 아주 작게 그린 그림을 굵은 펜으로 그리면 (5) 에서 크게 늘어나 선이 매우 굵어진다.
- 여러 물체·글자·낙서는 항상 범주 중 하나로 답한다 → 앱은 확률이 임계값(모델 설명서) 미만이면 "잘 모르겠어요" 로 보여 준다.
