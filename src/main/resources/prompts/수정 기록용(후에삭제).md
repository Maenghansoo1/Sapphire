# 프롬프트 수정 기록 (후에 삭제)

> ⚠️ **이 파일은 AI가 읽지 않습니다.**
> 서버가 쓰는 프롬프트는 `mission-create-prompt.md`(미션 생성)와 `mission-template-prompt.md`(틀별 상세)이며, 둘 다 **파일 이름을 지정해서** 불러옵니다. 틀 파일을 생성 프롬프트와 어떻게 함께 쓸지는 아직 정하는 중입니다. (제출 판정 프롬프트 `mission-judge-prompt.md`는 AI가 평가를 하지 않기로 해서 삭제했습니다.)
> 이 파일은 사람이 보는 기록용이며, 프롬프트 작업이 끝나면 삭제합니다.
>
> 나중에 prompts 폴더의 파일을 **한꺼번에** 불러오도록 코드를 바꾸면 이 파일도 AI에게 들어갈 수 있습니다. 그렇게 바꾸기 전에 이 파일을 먼저 지워 주세요.

## 기록 방법

프롬프트를 수정했으면 **아래 "수정 기록"의 맨 위에** 새 기록을 추가해 주세요. 최신 기록이 항상 위에 오도록 합니다.

```
### 날짜 — 이름
- 파일: 수정한 파일 이름
- 수정한 곳: 섹션 이름 (예: "그룹 관계에 맞추기 > 가족")
- 무엇을: 무엇을 추가, 삭제, 변경했는지
- 왜: 수정한 이유 (테스트 결과, 팀 회의 결정 등)
```

## 프롬프트를 고칠 때 주의할 점

1. **프롬프트 파일에 중괄호 `{ }`를 쓰지 마세요.** Spring AI가 값을 끼워 넣을 자리로 읽어서 서버 오류가 납니다. 이 기록 파일에서는 써도 괜찮습니다.
2. **결과 항목의 영어 이름은 바꾸지 마세요.** 코드와 이름이 같아야 AI 답변을 읽을 수 있습니다. 바꿔야 하면 백엔드 담당자와 먼저 이야기해 주세요.
   - 생성: `content`, `category`, `params`
   - `params`의 키는 틀마다 다른 빈칸 이름입니다: `subject`, `condition`, `color`, `sentence`, `tone`, `word`, `optionA`, `optionB`, `question`, `topic`, `left`, `right`, `a`, `b`, `seconds`
3. **틀은 서버가 정하고 AI는 고르지 않습니다.** 틀 코드와 빈칸 이름은 `docs/BACKEND/MISSIONS_API.md` §1 코드표(서버의 `MissionTemplate`)와 같아야 합니다. 새 틀을 추가하면 생성 프롬프트의 "틀과 빈칸"과 틀 파일에도 추가해 주세요.
4. **생성 프롬프트와 틀 파일이 같은 내용을 다르게 말하지 않게 해 주세요.** 한쪽에서 틀 규칙을 바꾸면 다른 쪽도 확인해 주세요.
5. **한 번에 하나씩 고쳐 주세요.** 여러 곳을 한꺼번에 고치면 어떤 수정이 효과가 있었는지 알기 어렵습니다.
